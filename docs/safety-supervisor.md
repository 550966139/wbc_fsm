# 23DoF 安全监控实现与验证边界

`CtrlComponents::configure23()` 装载策略配置；`FSM::run()` 按接收快照 → 检查状态 → 切换/计算 → 再检查状态和命令 → 发送的顺序运行。任一异常在同轮改为阻尼、退到 Passive 并锁存原因。23 个有效槽的阻尼为 Kp=0、Kd=3、q/dq/tau=0，其余六槽禁用且字段为零。

## 已实现

- CRC 错误、重复及倒序 LowState 不刷新接收时间；有效数据通过互斥锁形成快照。
- 四元数归一有效性、重力、关节数值/位置/速度、摇杆有限性检查。
- 目标位置上下限、与实测追踪误差、相邻目标跳变、配置 PD、零速度/力矩及不存在槽位检查。
- 倾角用 `abs(projected_gravity.z + 1)`，默认阈值 0.5、持续 40 ms 才锁存；不是直接用弧度角阈值。恢复阈值 0.15，需持续健康 500 ms。
- 50 Hz 控制使用单调时钟；计算或相邻循环间隔超过两个周期（40 ms）锁存阻尼。
- 独立约 500 Hz DDS 发布线程检查状态及控制命令 100 ms 超时，NaN/Inf 输出和发布失败会锁存。推理线程卡住时不继续永久发布旧动作。
- L2+B/SELECT 在接收回调中也立即锁存发布线程。故障恢复需要新的 START；该次仅解锁并留在阻尼，松开再按才能站立。通信恢复不会自动恢复旧动作。
- 真机启动前核对已释放的运动服务、有效状态、23DoF 机型值 4 和已有低层命令流。机型不符时不发布；运行中机型变化也禁止继续发送。
- 正常退出尝试发送 20 ms 阻尼；SIGKILL、进程崩溃、断电、网络中断无法保证这一步执行。

## 验证与限制

基础测试覆盖纯算法、配置拒绝和命令校验。完整构建的离线测试通过临时合成 ONNX 和 mock IO 覆盖实际适配器与 FSM；它不证明真实策略稳定，也不验证实际 DDS 收发时序、无线遥控断链行为或电机响应。

部署前仍需用真实策略进行 MuJoCo 和现场吊装测试，实测 PC2 的推理/循环耗时与看门狗时延，确认固件的低层超时保护。`rt/lowcmd` 的启动监听不是分布式互斥锁，不能阻止其他发布者稍后加入。

安全阈值是部署起点，并非已在此机器人上标定的认证边界；未实现的电机温度、电流、力矩/碰撞检测也不能由这些软件检查替代。真机验证步骤见 [23DoF 部署说明](g1-23dof-port.md)。
